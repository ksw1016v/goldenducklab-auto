# 인스타 자동화 키트: 다른 계정·다른 컨셉에 옮겨 쓰기

> 골든덕랩(@golden_duck_lab)에서 직접 만들고 고쳐 가며 검증한 **인스타 자동 게시 + 댓글 DM 자동 발송** 구조를,
> 어떤 계정·어떤 주제에도 다시 쓸 수 있게 정리한 문서입니다.
> 기준일 2026-11-13 · 원본 저장소 `ksw1016v/goldenducklab-auto` (공개)

**이 문서로 만들 수 있는 것**
1. 원고(JSON)만 채워 두면 정해진 요일·시간에 **카드뉴스·릴스가 자동으로 올라가는** 계정
2. 데이터(주가, 날씨, 순위 등)로 **원고까지 자동 생성**되는 시리즈 (예: 매일 경제 브리핑)
3. "댓글에 OOO 남기면 DM으로 알려드려요" → **자동 대댓글 + 게시물별 맞춤 DM**
4. 매일 성과(도달·저장·공유·시청 시간) 자동 수집

**드는 돈**: 0원. 공개 GitHub 저장소(실행 시간 무제한 무료)와 인스타 공식 API, Claude 예약 작업(하루 몇 번 짧게)만 씁니다.

## 0. 전체 그림

```
[원고 JSON] ─┐
[데이터 수집] ┴▶ 렌더링(카드 jpg · 릴스 mp4) ▶ 저장소에 커밋 ▶ 공개 주소(jsDelivr CDN)
                                                              │
         Claude 예약 작업(정시 실행 신호) ▶ GitHub Actions ──▶ 인스타 API 게시 ▶ state.json 기록
                                                              │
                         댓글 확인 봇(5분 간격, 3일) ◀────────┘ ▶ 자동 대댓글 + 게시물별 DM
                         성과 수집(매일) ▶ insights.json ▶ 다음 기획에 반영
```

| 역할 | 무엇으로 |
|---|---|
| 실행 엔진 | GitHub Actions (공개 저장소 = 무료) |
| 정시 실행 | **Claude 예약 작업**이 목표 시각 4분 전에 실행 버튼을 누름. GitHub 예약(cron)은 예비 |
| 이미지·영상 주소 | 저장소에 커밋한 파일을 jsDelivr CDN 주소로 (커밋 SHA 고정) |
| 화면 만들기 | HTML/CSS 템플릿 → Playwright(크롬)로 캡처, 릴스는 프레임 캡처 → ffmpeg |
| 배경음 | numpy로 직접 합성 (저작권 걱정 없음) |
| 비밀값 | GitHub Secrets `IG_TOKEN` 하나 |
| 기록 | `state.json` (무엇을 언제 올렸는지, 어떤 댓글에 답했는지) |

## 1. 처음 한 번: 인스타·Meta 연결 (사람이 직접 해야 하는 부분)

> 계정 만들기, 약관 동의, 본인 인증, 비밀번호·토큰 입력은 **계정 주인이 직접** 합니다. 토큰은 채팅·문서에 붙여 넣지 않습니다.

1. **인스타 계정을 프로페셔널(비즈니스/크리에이터)로 전환**
2. **Meta 개발자 계정** 만들기 (developers.facebook.com). "API 접근 차단"이 뜨면 개발자 계정 인증부터 합니다.
3. **비즈니스 포트폴리오** 만들기 (business.facebook.com). 여러 계정을 묶을 대표 브랜드 이름으로 만듭니다.
   - 예: '스텔라미디어' 아래에 골든덕랩, 대나무숲 등
4. **앱 만들기** → 이용 사례 "Instagram에서 메시지 및 콘텐츠 관리"를 고르고 **통합 로그인(Unified login)** 방식을 씁니다.
5. 앱 → 이용 사례 → **권한 및 기능**에서 추가할 권한

   | 권한 | 용도 |
   |---|---|
   | `instagram_basic` | 계정·게시물 읽기 |
   | `instagram_content_publish` | 게시 |
   | `instagram_manage_comments` | 댓글 읽기·대댓글 |
   | `instagram_manage_messages` | DM(댓글 비공개 답장) |
   | `instagram_manage_insights` (+ `instagram_business_manage_insights`) | 성과 수집 |

6. 통합 로그인 화면의 **"1. 앱 구성" → 권한 수정**에서, 토큰을 만들 때 쓰는 구성(Configuration)에도 같은 권한을 체크합니다.
   - **함정**: 앱에만 권한을 넣고 구성에 빠져 있으면, 새 토큰에도 권한이 들어가지 않습니다.
7. **비즈니스 자산 그룹**에 인스타 계정, 앱, 본인(전체 관리)을 넣습니다.
   - 설정 → 계정 → 비즈니스 자산 그룹 → 자산 할당·사람 할당
8. **"2. 액세스 토큰 생성" → 토큰 생성** → 권한 허용 → 토큰 복사 → GitHub 저장소 Settings → Secrets → `IG_TOKEN`에 저장합니다.
   - 통합 로그인의 시스템 사용자 토큰(SUAT)은 **만료가 없어요**. 인스타 로그인 토큰(`IG...`)은 60일이라 매달 연장 작업이 필요해요.
   - **토큰의 권한은 발급하는 순간 고정됩니다.** 나중에 권한을 추가하면 토큰을 새로 발급해야 해요.
9. 계정의 숫자 ID(`IG_USER_ID`)를 `publish.py`에 넣습니다.

**개발 모드로도 충분했던 것**: 내 계정에 게시, 댓글 읽기·대댓글, 그리고 **일반 사용자에게 댓글 비공개 답장 DM** (2026-11-12 실제 시험에서 성공). 앱 검수는 필요하지 않았어요.

## 3. 원고 형식

```json
{
  "series": "시리즈 이름",
  "theme": "테마 키 (render.py THEMES)",
  "kind": "릴스 장면 종류 (없으면 기본)",
  "no": 1,
  "slug": "basic-01  ← 고유 ID이자 out/ 폴더 이름, 접두사로 시리즈를 구분",
  "slides": [ {"type": "cover", ...}, {"type": "list", ...}, ..., {"type": "end", ...} ],
  "caption": "캡션 + 해시태그"
}
```
- 슬라이드 타입은 `render.py`의 템플릿과 1:1로 대응합니다. 지금 있는 타입: `cover`, `list`, `check`, `etf_info`, `dca`, `need`, `health`, `calendar`(색 그룹 달력), `end`
- 강조: `<mark>`(형광펜), 줄바꿈 `<br>`
- 렌더링하면서 글자가 칸을 넘치면 `!! overflow` 경고가 납니다. 글자를 줄여서 해결해요.

## 4. 게시 워크플로 틀 (시리즈 1개 = 파일 1개)

```yaml
on:
  schedule: [ ... 목표 시각 앞뒤로 5~7개, 정각은 피해서 ... ]   # 예비
  workflow_dispatch:                                              # Claude 예약 작업이 누르는 버튼
permissions: { contents: write, actions: write }
concurrency: instagram-post          # 모든 게시 작업이 동시에 하나만
jobs:
  post:
    steps:
      - checkout
      - setup-python 3.12            # ← 꼭 고정 (아래 '사고 기록' 참고)
      - git pull → python3 guard.py <시리즈>     # 오늘 이미 올렸나? 요일·시간 맞나?
      - 다음 원고 고르기(대기열 or 자동 생성) → 없으면 경고 남기고 종료
      - 한글 폰트 복사 + playwright 설치(러너의 크롬 사용)
      - 렌더링 → out/<slug>/ 커밋·푸시 → SHA 확보
      - IMAGE_BASE=https://cdn.jsdelivr.net/gh/<repo>@<SHA> , 20~45초 대기
      - publish.py post|reel → state.json 커밋·푸시
      - (선택) 릴스 추가 게시: continue-on-error
```

### guard.py 규칙
- 시리즈마다 **하루 1편**: `state.json` 로그의 slug 접두사로 시리즈를 판단해요. 접두사가 겹치지 않게 해 주세요(예: `toon-`이 기초편으로 잘못 세지던 사고가 있었어요).
- `TARGET`: 목표 시각. **15분 전부터만** 게시를 허용해요.
- `DAYS`: 올리는 요일 (월=0)
- `LATE`: 이 시각이 지나면 그날은 건너뛰어요. 아침 브리핑이 오후에 올라가는 일을 막는 용도예요.
- 수동 실행(`workflow_dispatch`)은 요일·시간 조건을 무시하고 중복 조건만 봐요.
- 저녁 시리즈는 하루의 경계를 낮 12시로 볼 수 있어요. 새벽에 늦게 올라간 편은 전날 몫으로 쳐요.

### 정시 실행: Claude 예약 작업 프롬프트 (그대로 복사해서 이름·파일만 바꾸기)
```
OOO 인스타 자동 게시용 실행 신호를 보내는 작업입니다. 아래 명령 하나만 실행하고 끝내세요(다른 작업·수정 금지).

gh api -X POST repos/<owner>/<repo>/actions/workflows/<file>.yml/dispatches -f ref=main

성공하면 "<file> 실행 요청 완료"라고만 한국어로 답하세요. 실패하면 오류 메시지를 그대로 보고하세요.
같은 날 이미 게시됐는지는 워크플로가 스스로 확인하므로 신경 쓰지 않아도 됩니다.
```
- 시각은 `CRON_TZ=Asia/Seoul 56 20 * * 1,3,5`처럼 목표보다 **4분 앞**, 정각이 아닌 분으로 잡아요.
- 렌더링에 2~4분이 걸려서, 이렇게 하면 실제 게시는 목표 시각 무렵이 돼요.

## 5. 릴스 만들기

- **원리**: 장면마다 HTML 한 장을 만들고, 요소에 `data-*` 시간표를 붙여요. 페이지 안의 `setT(t)` 함수가 그 시각의 모습을 그리고, 이걸 1/30초마다 캡처해서 ffmpeg로 mp4를 만들어요. 1080×1920, 30fps, H.264 + AAC예요.
- **애니메이션 속성** (`reel_anim.py`)

  | 속성 | 효과 |
  |---|---|
  | `data-in="t"` | 아래에서 올라오며 나타남 |
  | `data-pop="t"` | 톡 튀어나옴 |
  | `data-drop="t"` | 위에서 떨어짐 |
  | `data-zoom="t"` | 확대되며 나타남 |
  | `data-count="시작,길이"` + `data-from/to/fmt` | 숫자 카운트업 (`won`=만원 표기, `num`+`data-dec/pre/suf`) |
  | `data-draw="t"` | 선 그래프가 그려짐 (`pathLength="1"`) |
  | `data-shake="시작,길이,세기"` | 덜덜 흔들림 (긴장감) |
  | `data-win="시작,끝"` | 그 구간에만 보임 (3·2·1 카운트다운) |
  | `data-bar="시작,길이"` | 막대가 줄어듦 (타이머) |
  | `data-blink="t"` | 깜빡임 |

- **표지(cover.jpg)**: 따로 만들어 `cover_url`로 같이 올려요. 안 그러면 릴스 미리보기가 빈 첫 프레임이 돼요.
- **배경음**: `music()`은 잔잔한 로파이, `music_tense()`는 단조 드론에 심장박동 같은 킥이 점점 빨라지고 째깍 소리와 끝 상승음이 붙어요(퀴즈용).
- **길이**: 18~32초. 성과 분석 결과 평균 시청이 4~9초라서 **첫 장면에 결론 숫자**를 보여 줘요.

## 6. 댓글 → 자동 대댓글 + 게시물별 DM (퍼널)

### 흐름
```
릴스: "정답(자료)이 궁금하면 팔로우하고 댓글에 '키워드'"
   ↓ 게시 직후 quiz-dm 시작 (5분마다 댓글 확인, 3일간)
키워드 댓글 발견 → ① 그 게시물의 원고에 적힌 DM 문구로 비공개 답장(DM)
                  ② 대댓글 "DM 보냈어요 📩 안 보이면 메시지 요청함 확인" (5가지 돌려쓰기)
                  ③ state.json 에 댓글 ID 기록 → 다시 보내지 않음
```

### 핵심 코드 (요점만)
```python
# 비공개 답장(DM): 댓글 ID로 보냄. 댓글 1개당 1통, 7일 이내만 가능
POST /{IG_USER_ID}/messages  recipient={"comment_id": cid}  message={"text": 정답문구}
# 대댓글
POST /{comment_id}/replies   message=문구
# 댓글 읽기
GET  /{media_id}/comments?fields=id,text,username,timestamp
```
- **게시물별 DM**: 게시할 때 `state.json`의 `quiz_media`에 `{media_id: 원고 경로}`를 기록해 둬요. 봇은 댓글이 달린 게시물의 원고에서 DM 문구를 꺼내요.
- **키워드 인식**: 공백과 `!~.?`를 지우고 포함 여부로 판단해요. '골든덕', '골든 덕!', '골든덕랩' 모두 인식돼요. 내 계정이 단 댓글은 제외해요.
- **5분 간격 3일 실행** (무료): 한 번 돌 때 약 5시간 50분 동안 5분마다 확인하고, 끝나면 **스스로 다시 실행**해요(`gh workflow run`, `permissions: actions: write`). 마지막 게시 후 3일이 지나면 멈춰요(`quiz/active.py`).
  - GitHub 예약 기능을 쓰지 않아서 밀리지 않아요.
  - 혹시 끊기면 Claude 예약 작업이 **하루 1번** 점검해서 다시 켜요.
  - Claude 예약으로 5분마다 돌리는 건 불가능해요(최소 1시간 간격). 가능하더라도 3일이면 864번 실행이라 비효율적이에요.

### 꼭 알아야 할 인스타 규칙
- **팔로우 여부는 확인할 수 없어요.** 상대가 DM 버튼을 눌러 대화를 시작해야만 알 수 있어요. 그래서 "팔로우하고 댓글"로 **부탁**만 해요.
  - 꼭 팔로우를 확인하고 보내야 한다면 CreatorFlow 같은 유료 도구(월 $15 안팎)의 Follow Gate를 써요.
- **DM은 '메시지 요청함'으로 가요.** 내가 팔로우하지 않는 계정이 처음 보낸 DM은 요청함으로 가요. 그래서 대댓글·릴스·캡션에 "안 보이면 메시지 요청함" 안내를 넣어요. 상대가 나를 팔로우했거나 한 번 답장하면 받은 편지함으로 와요.
- DM 끝에 **질문 하나**를 넣어요("맞히셨나요? 답장으로 알려 주세요"). 답장이 오면 대화창이 열리고 다음 DM부터 받은 편지함으로 가요.
- 같은 문구를 반복하면 스팸으로 볼 수 있으니 대댓글은 돌려써요.

### 시험하는 법
1. 다른 개인 계정으로 아무 게시물에 키워드 댓글을 달아요.
2. `quiz-dm` 워크플로를 `test=1`로 실행해요(최근 게시물 전체를 대상으로 한 번만).
3. 대댓글과 DM(요청함 포함)을 확인해요. 서버에 남은 대화 기록은 `test=check`로 볼 수 있어요.

## 7. 콘텐츠 기획 공식 (주제만 바꿔 쓰기)

### 후킹 채점 (100점, 60점 미만이면 다시 쓰기)
구체성 30 · 나와의 관계 25 · 핵심어가 앞 10자 안에 20 · 궁금증 15 · 짧음 10
**바로 탈락**: 인사로 시작, "스크롤 멈추세요", 근거 없는 숫자, 과장·보장 표현

### 반응이 좋았던 형식 (골든덕랩 실제 성과, 2026-11)
| 형식 | 결과 |
|---|---|
| **릴스 vs 카드뉴스** | 같은 편인데 릴스 도달이 **100~200배** (카드 5~17명, 릴스 196~2,570명) |
| "~했다면 지금 얼마?" 숫자 릴스 | 가장 많이 퍼짐 (SCHD 2,570명, 저장 17) |
| 첫 장면에 결론 숫자 | 평균 시청이 4~9초라 필수 |
| 종목 숨김 퀴즈 + 댓글 키워드 DM | 댓글·팔로우 유도용 |

### 퀴즈 유형 틀 (`quiz/make_quiz.py`의 `유형:대상`)
| 유형 | 첫 화면 | 다른 컨셉 예시 |
|---|---|---|
| `dca` 결과 숫자 | "월 10만원씩 10년, 1,200만원이 8,132만원" | 다이어트: "하루 30분씩 3개월, -8kg 된 운동은?" |
| `coffee` 생활 단위 환산 | "매일 커피 한 잔 값을 10년 모았더니" | 육아: "하루 15분 책 읽기 1년이면 몇 권?" |
| `trap` 함정 | "월 100만원 배당, 단 884만원으로?" → DM에서 원금 −90% 공개 | 여행: "왕복 9만원 항공권, 숨은 비용은?" |
| (예정) 연도별 막대, A vs B, 폭락날 샀다면 | | |

릴스 구성은 모든 유형이 같아요(약 19초).
1. 결론 숫자 + 흔들림
2. 가려진 정답 ▨▨▨ + 줄어드는 타이머 + 힌트 3개
3. 정답 공개까지 3·2·1 → 🔒
4. 정답 받는 법 (팔로우 + 댓글 키워드)

## 8. 사고 기록과 해결법 (같은 실수 안 하기)

| 증상 | 원인 | 해결 |
|---|---|---|
| 예약한 게시가 4~8시간 늦게 올라가거나 안 올라감 | GitHub cron 지연·누락 (특히 정각) | **Claude 예약 작업으로 정시 실행**, cron은 정각을 피해 여러 개를 예비로 |
| 갑자기 모든 게시 실패 (`greenlet` 설치 오류) | 러너 기본 파이썬이 3.14로 바뀜 | 모든 워크플로에 `setup-python 3.12` 고정 |
| 카드는 올라갔는데 릴스만 실패 (컨테이너 ERROR) | 방금 올린 영상이 CDN에 아직 없음 | 게시 전 20~45초 대기 + 릴스 **1분 간격 3회 재시도** + `reel-retry.yml`(릴스만 다시) |
| 같은 편 두 번 게시 | 실행이 겹침 | `concurrency` + `guard.py` + 가드 전에 `git pull` |
| 한 시리즈 게시가 다른 시리즈로 세짐 | slug 접두사 판정 누락 | 시리즈마다 고유 접두사, `guard.py`에 등록 |
| 성과 수집 "권한 없음" | 토큰에 인사이트 권한 없음 | 앱 권한 + **로그인 구성 권한** 추가 → 토큰 **재발급** |
| 토큰 생성 시 페이스북 로그인만 반복 | 비즈니스 자산 그룹에 인스타 계정 없음 | 자산 그룹에 계정·앱·사람 할당 |
| 한글 폰트 설치에 8분 넘게 걸림 | apt 패키지 설치 | `fonts/`에 필요한 폰트만 넣고 복사 (5초) |
| 릴스 미리보기가 비어 있음 | 첫 프레임이 빈 화면 | 표지 이미지를 따로 `cover_url`로 |
| DM이 안 왔다고 함 | 메시지 요청함으로 감 | 안내 문구 추가, 서버 기록은 `dm_check.py`로 확인 |
| 실패를 늦게 앎 | | GitHub이 실패 메일을 보내요. 메일 제목의 워크플로 이름으로 원인 확인 |

- [ ] 프로페셔널 계정 · 개발자 계정 · 비즈니스 포트폴리오 · 앱(통합 로그인)

- [ ] 원본 저장소를 템플릿으로 새 공개 저장소 만들기 (공개여야 CDN과 무료 실행 가능)

- [ ] `assets/`(로고·캐릭터), `fonts/`, `render.py` 테마 색 교체
- [ ] 시리즈 정하기 → slug 접두사, `guard.py`의 `TARGET`·`DAYS`·`LATE`
- [ ] 시리즈별 게시 워크플로 복제 (`setup-python 3.12`, `concurrency: instagram-post`)

- [ ] 샘플 렌더링해서 눈으로 확인 (글자 넘침, 표지, 릴스 장면)
